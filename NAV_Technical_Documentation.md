**Дата:** 2026-06-11

## 1. Обзор проекта

### 1.1 Цель

Проект представляет собой инструмент командной строки для автоматического анализа объектов Microsoft Dynamics NAV (версии 2013–2015) и генерации структурированной технической документации в формате Markdown.

Документация создаётся для целей **миграции системы** на платформу Business Central (AL), а также может использоваться как эталонная база для любого рефакторинга или расширения.

### 1.2 Ключевые возможности

| Возможность | Описание |
|---|---|
| Парсинг `.txt` | Полный разбор текстового экспорта объектов NAV |
| Парсинг `.fob` | Извлечение объектов из бинарного формата NAV |
| Генерация Markdown | Структурированная документация с навигацией |
| Миграционные аннотации | Автоматические пометки о сложности перехода на BC |
| Код и триггеры | Документирование всех C/AL процедур и триггеров |

### 1.3 Поддерживаемые объекты NAV

| Тип | ID | Примечание к миграции |
|---|---|---|
| Table | 1 | Переносится в AL, проверить BLOB и устаревшие типы |
| Form | 2 | ⚠️ Удалён в BC — требует полного редизайна как Page |
| Report | 3 | Требует конвертации макета в RDLC или Word |
| Dataport | 4 | ⚠️ Удалён в BC — заменить на XMLport или Data Exchange |
| Codeunit | 5 | Переносится с минимальными изменениями |
| XMLport | 6 | Прямой аналог в AL |
| MenuSuite | 7 | Заменяется моделью Role Center |
| Page | 8 | Прямой аналог в AL |
| Query | 9 | Прямой аналог в AL |

### 2.3 Модель данных

Каждый распарсенный объект NAV представлен как Python `dict` со следующей структурой:

```python
{
    'type':       str,        # 'Table' | 'Codeunit' | 'Page' | ...
    'id':         int,        # Числовой ID объекта NAV
    'name':       str,        # Имя объекта
    'properties': dict,       # Словарь свойств объекта (CaptionML, SourceTable...)
    'fields':     list[dict], # Только для Table: список полей
    'keys':       list[dict], # Только для Table: список ключей/индексов
    'controls':   list[dict], # Только для Page/Form: элементы управления
    'triggers':   list[dict], # Список триггеров (OnInsert, OnModify...)
    'procedures': list[dict], # Список процедур (PUBLIC/LOCAL PROCEDURE)
    'raw_code':   list[str],  # Сырые строки кода из секции CODE
}
```

**Структура элемента `fields`:**
```python
{
    'no':         int,   # Номер поля
    'name':       str,   # Имя поля
    'type':       str,   # Тип данных (Code20, Text50, Decimal...)
    'properties': dict,  # TableRelation, CalcFormula, FieldClass...
}
```

**Структура элемента `triggers` / `procedures`:**
```python
{
    'name': str,  # Имя триггера или процедуры
    'body': str,  # Полный C/AL код блока
}
```

## 3. Детальное описание компонентов

### 3.1 NavTxtParser

**Файл:** `nav_to_markdown.py`, класс `NavTxtParser`  
**Назначение:** Разбор текстового экспорта NAV (`.txt`).

#### Алгоритм парсинга

1. Файл считывается целиком как строка с `encoding='utf-8'`
2. Разбивается на блоки по регулярному выражению `^OBJECT\s` (начало каждого объекта)
3. Каждый блок разбирается методом `_parse_object_block()`
4. Заголовок объекта извлекается регулярным выражением `OBJECT_HEADER_RE`
5. Тело блока разбивается на секции по ключевым словам (`FIELDS`, `KEYS`, `CODE`, `CONTROLS`...)
6. Каждая секция обрабатывается специализированным методом

#### Ключевые методы

| Метод | Назначение |
|---|---|
| `parse_file(filepath)` | Читает файл и вызывает `parse_text()` |
| `parse_text(content)` | Разбивает текст на объекты |
| `_parse_object_block(block)` | Парсит один объект NAV |
| `_parse_sections(lines, obj)` | Определяет и диспетчеризует секции |
| `_parse_fields(lines)` | Разбирает секцию `FIELDS` |
| `_parse_keys(lines)` | Разбирает секцию `KEYS` |
| `_parse_code(lines)` | Разбирает секцию `CODE` — выделяет триггеры и процедуры |
| `_parse_controls(lines)` | Разбирает секцию `CONTROLS` |
| `_extract_field_props(text)` | Извлекает свойства поля (TableRelation, CalcFormula...) |

#### Особенности формата .txt (NAV 2013–2015)

- Поля описываются в формате `{ no ; flags ; name ; type ; [props] }`
- Секции обозначаются ключевыми словами на отдельной строке (без отступа или с отступом)
- Код использует `BEGIN...END` блоки, а не фигурные скобки
- Триггеры начинаются с `ON` (например, `OnInsert()`, `OnModify()`)
- Процедуры начинаются с `PROCEDURE` или `LOCAL PROCEDURE`

### 3.2 NavFobParser

**Файл:** `nav_to_markdown.py`, класс `NavFobParser`  
**Назначение:** Извлечение объектов из бинарного формата `.fob`.

#### Алгоритм

1. Файл считывается как бинарные данные
2. В бинарных данных сканируются сигнатуры zlib-потоков (`0x78 0x9C`, `0x78 0xDA`, `0x78 0x01`, `0x78 0x5E`)
3. Для каждой найденной позиции пытается разархивировать данные нарастающими чанками
4. Успешно разархивированные блоки, содержащие ключевое слово `OBJECT`, передаются в `NavTxtParser`
5. Результаты дедуплицируются по паре `(type, id)`

#### Важное замечание

Формат `.fob` является проприетарным и недокументированным. Описанный подход работает для NAV 2013–2015, однако может не работать для более ранних версий или кастомизированных экспортов. **Рекомендуется** использовать `.txt` экспорт как основной источник — он надёжнее и полнее.

### 3.3 MarkdownGenerator

**Файл:** `nav_to_markdown.py`, класс `MarkdownGenerator`  
**Назначение:** Генерация Markdown-документации из списка объектов.

#### Структура генерируемого документа

```
# Заголовок документа (метаданные, дата, кол-во объектов)
## Table of Contents
## Summary Statistics        ← таблица по типам с оценкой сложности миграции
## Migration Overview        ← группировка по приоритету (🔴🟡🟢)
## Tables                    ← детальные секции по каждому типу объектов
## Pages
## Codeunits
## Reports
...
```

#### Миграционные аннотации

Класс содержит константный словарь `BC_MIGRATION_NOTES` с аннотациями для каждого типа объектов. Аннотации отображаются в начале каждой секции типа.

#### Оценка сложности миграции

| Цвет | Типы | Критерий |
|---|---|---|
| 🔴 Высокая | Form, Dataport | Нет прямого аналога в BC |
| 🟡 Средняя | Table, Codeunit, Report, MenuSuite | Требуется рефакторинг |
| 🟢 Низкая | Page, XMLport, Query | Прямой аналог в AL |

## 4. Интерфейс командной строки

### 4.1 Синтаксис

```bash
python nav_to_markdown.py [OPTIONS]
```

### 4.2 Параметры

| Параметр | Тип | Описание |
|---|---|---|
| `--txt FILE [FILE...]` | Список файлов | Один или несколько `.txt` файлов экспорта |
| `--fob FILE [FILE...]` | Список файлов | Один или несколько `.fob` файлов экспорта |
| `--dir DIRECTORY` | Путь | Директория — все `.txt` и `.fob` файлы из неё |
| `--output FILE` | Путь | Путь к выходному `.md` файлу (по умолчанию: `nav_documentation.md`) |

### 4.3 Примеры использования

```bash
# Разобрать один .txt файл
python nav_to_markdown.py --txt AllObjects.txt --output docs.md

# Разобрать один .fob файл
python nav_to_markdown.py --fob AllObjects.fob --output docs.md

# Оба формата одновременно (дедупликация по type+id, .txt имеет приоритет)
python nav_to_markdown.py --txt objects.txt --fob objects.fob --output docs.md

# Все файлы из директории
python nav_to_markdown.py --dir ./nav_exports/ --output docs.md

# Несколько .txt файлов из разных модулей
python nav_to_markdown.py --txt sales.txt purchase.txt inventory.txt --output full_docs.md
```

### 4.4 Экспорт объектов из клиента NAV

Для получения `.txt` файла из NAV 2013–2015:

1. Открыть **Object Designer** (`Tools → Object Designer`)
2. Выделить нужные объекты (или `Ctrl+A` — выбрать все)
3. `File → Export...`
4. Выбрать формат **Text** (`.txt`)
5. Сохранить файл

> **Совет:** Экспортировать объекты по типам (отдельно Tables, отдельно Codeunits и т.д.) для удобства последующего анализа.

## 6. Расширение проекта

### 6.1 Добавление нового типа объектов NAV

Чтобы добавить поддержку нового типа объекта (например, `Permission Set`):

1. Добавить тип в словарь `OBJECT_TYPES` в начале файла:
   ```python
   OBJECT_TYPES = {
       ...
       10: "PermissionSet",
   }
   ```

2. Если тип имеет уникальные секции — добавить их в `SECTION_KEYWORDS`:
   ```python
   SECTION_KEYWORDS = {
       ...
       "PERMISSIONS",
   }
   ```

3. Добавить обработчик в `NavTxtParser._flush_section()`:
   ```python
   elif section == 'PERMISSIONS':
       obj['permissions'] = self._parse_permissions(buffer)
   ```

4. Написать метод `_parse_permissions(lines)` по аналогии с `_parse_fields()`.

5. Добавить миграционную аннотацию в `MarkdownGenerator.BC_MIGRATION_NOTES`.

6. Добавить оценку сложности в метод `_summary_stats()`.

### 6.3 Добавление нового формата вывода

Проект легко расширяется на другие форматы документации:

| Формат | Рекомендуемый подход |
|---|---|
| HTML | Заменить строковые шаблоны в `MarkdownGenerator` на Jinja2 |
| PDF | Конвертировать Markdown → PDF через `pandoc` |
| Word (.docx) | Использовать библиотеку `python-docx` или `docx-js` |
| Excel | Использовать `openpyxl` для выгрузки таблиц полей |
| JSON | Сериализовать список объектов через `json.dumps()` |

Пример реализации генератора JSON:

```python
import json

class JsonGenerator:
    def generate(self, objects: list, source_files: list) -> str:
        return json.dumps({
            'generated': datetime.now().isoformat(),
            'source_files': source_files,
            'objects': objects,
        }, ensure_ascii=False, indent=2)
```

## 7. Известные ограничения

| Ограничение | Описание | Обходной путь |
|---|---|---|
| `.fob` надёжность | Бинарный формат не документирован Microsoft | Использовать `.txt` как основной источник |
| Вложенные объекты | Объекты внутри Report DataItems не разбираются полностью | Ручная проверка сложных отчётов |
| Размер кода | Процедуры длиннее 2000 символов обрезаются в документе | Константа легко изменяется в `MarkdownGenerator._object_section()` |
| NAV < 2013 | Более старые версии NAV имеют другой формат `.txt` | Потребуется адаптация регулярных выражений |
| Кодировка | Ожидается UTF-8; некоторые старые NAV могут экспортировать в cp1252 | Изменить `encoding=` в `parse_file()` |
