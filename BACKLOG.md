## EPIC 1 — NAV 2009 Compatibility  🔴 HIGH PRIORITY

### US-01 · Автодетект кодировки файла
**Проблема:** NAV 2009 Classic Client экспортирует .txt в OEM-кодировке (cp437/cp850/cp1252), не UTF-8.  
**Решение:** Автодетект через chardet + fallback-цепочка кодировок в `parse_file()`.  
**Параметр CLI:** `--encoding auto|utf-8|cp1252|cp850|cp437`  
**Статус:** TODO

### US-02 · Нормализация типов OemCode / OemText
**Проблема:** До NAV 2013 строковые типы полей называются `OemCode20`, `OemText50`.  
**Решение:** Метод `_normalize_field_type()` с заменой + флаг в документации "legacy type".  
**Статус:** TODO

### US-03 · Парсинг классического макета отчётов (SECTIONS / REQUESTFORM)
**Проблема:** NAV 2009 Reports содержат секции `SECTIONS` (классический layout) и `REQUESTFORM`.  
**Решение:** Добавить секции в `SECTION_KEYWORDS`, извлекать структуру колонок/групп/итогов.  
**Статус:** TODO

### US-04 · Парсинг OBJECT-PROPERTIES (дата, версия)
**Проблема:** Дата модификации и Version List теряются — полезны для определения возраста объекта.  
**Решение:** Разбирать секцию `OBJECT-PROPERTIES` и добавлять в dict объекта.  
**Статус:** TODO

### US-05 · Режим совместимости в CLI
**Решение:** Параметр `--nav-version 2009|2013|2015|auto` включает нужные адаптации.  
**Статус:** TODO

## EPIC 2 — Migration Intelligence  🔴 HIGH PRIORITY

### US-07 · Таблица переменных объекта
**Описание:** Для каждого объекта извлекать секцию `VAR` и строить таблицу:
имя переменной, тип, описание (Record/Codeunit → имя объекта), область видимости (локальная/глобальная).  
**Статус:** TODO

### US-08 · Таблица входных/выходных параметров процедур
**Описание:** Для каждой процедуры разбирать сигнатуру: имя параметра, тип, направление (VAR = in/out), возвращаемый тип.  
**Статус:** TODO

### US-09 · Комментарии для ролей участников миграции
**Описание:** Для каждого объекта генерировать три блока:
- 🏗️ **Архитектор** — зависимости, паттерны, критические точки, риски переноса
- 💻 **Разработчик** — конкретные deprecated функции, что переписать, сложность в часах (оценка)
- 📋 **Проект-менеджер** — приоритет, зависимости от других объектов, риск для бизнеса  
**Статус:** TODO

### US-10 · Структура данных отчёта (для переноса в другие генераторы)
**Описание:** Для объектов типа Report документировать:
- DataItems (иерархия, таблицы-источники, фильтры)
- Columns (поля, выражения CalcFields)
- Группировки и сортировки
- Параметры запроса (RequestForm/RequestPage)
- Рекомендации: RDLC / Word layout / Power BI / SSRS  
**Статус:** TODO

### US-11 · Граф зависимостей между объектами
**Описание:** Сканировать код на вызовы `CODEUNIT.RUN`, `PAGE.RUN`, `REPORT.RUN`, `FORM.RUN`, `COMMIT`, `TRANSFERFIELDS` и строить матрицу зависимостей.  
**Выход:** Секция "Dependencies" в документации + опциональный Mermaid-граф.  
**Статус:** TODO

### US-12 · Детектор устаревших и критичных паттернов
**Описание:** Статический анализ кода — поиск:
- Вызовов `FORM.*`, `DATAPORT.*` (удалены в BC)
- `LOCKTABLE`, `COMMIT` в неожиданных местах (риск транзакций)
- `CODEUNIT.RUN` без обработки ошибок
- Хардкод-значений (магические числа, строки)
- `CALCFIELDS` в циклах (проблема производительности)  
**Статус:** TODO
